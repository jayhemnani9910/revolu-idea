CAG Deep Research

A research CLI on LangGraph. It turns a question into a causal graph, has an adversary and a supporter agent search for evidence on each link, judges them, and writes a report. Ports/adapters layout. Experimental.

Quick start

Clone, install, configure .env, run:

git clone https://github.com/jayhemnani9910/revolu-idea.git
cd revolu-idea
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# copy template, then set LLM_API_KEY
cp .env.example .env

python main.py "What are the latest developments in quantum computing?"

# no-key smoke run
LLM_PROVIDER=mock SEARCH_PROVIDER=mock python main.py "test topic"

How it works

The planner turns the query into a causal DAG. The auditor runs safety checks (loops, depth), the selector picks the next edge, and the adversary and supporter search for evidence on it in parallel. The judge gives a verdict and confidence, then control goes back to the auditor. When no edges are left or max depth is hit, the writer saves output/reports/*.md + .json.

Providers

  • LLM: OpenAI-compatible APIs (Groq/DeepSeek/etc) via LLM_BASE_URL.
  • LLM (no key): LLM_PROVIDER=mock for local smoke runs.
  • Search: Tavily / Exa (keys) or SEARCH_PROVIDER=duckduckgo (free).
  • Storage: local filesystem (OUTPUT_DIR).

Settings load from .env (gitignored). Core env vars:

  • LLM_PROVIDER, LLM_BASE_URL, LLM_MODEL, LLM_API_KEY
  • SEARCH_PROVIDER (+ TAVILY_API_KEY or EXA_API_KEY if used)
  • MAX_RECURSION_DEPTH, MAX_INVESTIGATIONS_PER_EDGE
  • OUTPUT_DIR

Repo tour

  • main.py — CLI entrypoint (runs the research graph).
  • container.py — provider wiring (LLM/Search/Storage).
  • graph/ — LangGraph workflow construction.
  • agents/ — graph nodes + shared state.
  • ports/ + adapters/ — interfaces + implementations.
  • domain/ — core models (citations, evidence, reports, graphs).

Outputs

Artifacts are written under output/:

  • output/reports/*.md + *.json — final report

The report includes citations, findings, and verification status.

Key features

  • LangGraph workflow: planner → selector → adversary + supporter → judge → writer.
  • One search provider per run: Tavily, Exa, or DuckDuckGo (Wikipedia fallback).
  • Causal graph: variables and edges, each edge gets a verdict and confidence.
  • Ports/adapters design so providers can be swapped without touching the core flow.
